# Plugin Card format (Phase 4)

One card per deep-research plugin. Extract the full feature list, not just headline bullets — use `feature-categories.md` as a checklist. In the Research Report, show a short version (key stats, top features, love/hate, weak spot); the full card goes to the appendix and the workbook.

```
### [Plugin name] — [seller]
- Link:
- Price: Free / Pro tiers (yearly / lifetime / per-site)
- Installs or sales:
- Rating: X/5 from N reviews
- Last update: date — Active / Slow / Abandoned
- Compatibility: HPOS? Checkout Blocks? Tested up to WP x.x / WC x.x?
- Health metrics (see references/analytics-playbook.md §2): age, install velocity,
  momentum, update cadence, negative review share, support resolution rate,
  support load, vulnerability history

FULL FEATURE LIST (grouped by category — see references/feature-categories.md)
| Category | Feature | Free / Pro | Notes (how well it works) |

- Recently added features (from changelog):
- Features users request but don't have (from support/reviews):
- What users love (4–5★):
- What users hate (1–3★ + support threads):
- Support quality: share of recent threads resolved, reply speed
- Weak spot we can beat:
- Messaging: headline promise, main proof (numbers, logos, reviews), offer (free trial, refund days, discount, lifetime deal), main call to action
- Mini SWOT: Strengths / Weaknesses / Opportunities for us / Threats to us (one line each)
```
